# Status: what works and what remains

This page lists ClassRevive's capabilities with the evidence behind them and the work that remains. Nothing here claims universal recovery of original source: obfuscation, missing dependencies and information discarded by compilation can prevent a faithful reconstruction. For numbers, see [benchmarks](benchmarks.md), which also explains how to run the scoreboard yourself.

| Area | What works today (evidence) | Remaining work |
|---|---|---|
| Engines and selection | CFR, Vineflower, Procyon and JADX run as separate JVM workers with stable outcome codes. Candidates are ranked by recompilation, structural signature coverage (each class weighted equally), javac errors, per-method round trip and placeholder signals. Bounded hybrids mix files guided by javac's per-file errors; bounded source repairs fix common decompiler errors; per-method composition takes a method body from another engine only when it recompiles and its round trip is identical or equivalent (tests, benchmark corpus, scoreboard) | Exhaustive search is not attempted; behavioral equivalence is not verified |
| Recompilation and round trip | javac in a worker with `-proc:none`, an empty source path and either an empty class path or explicit local JARs; Java 1.1..21 inputs (1.1..7 with `--release 8`); per-method bytecode round trip with normalizations for javac variations and decompiler rewritings that keep JVM semantics; inferred stubs for missing libraries, with stub-backed results marked as such | Java 22+ inputs report `UNSUPPORTED_RELEASE` under JDK 21; generic signatures, annotations and constant values are not compared |
| Readable fallback | ASM dump of the original instructions when recovery is partial; ASM 9.11.1 parses class versions through Java 28 | — |
| Static simplification | Opt-in, bounded passes: integer constant and branch folding (output passes the JVM verifier), adjacent string operations, and a static interpreter for pure single-`String` decoder methods with an explicit allowlist and time/memory budgets (see [pass API](pass-sdk.md)) | Broader opcode and data-flow patterns, each with authored regression fixtures |
| Obfuscation detection | Static technique profile and obfuscator hypotheses with scores and reasons (see [obfuscation detection](obfuscation-detection.md)); clean library jars give `none` | Rules for more tools; data-flow based opaque predicates |
| Obfuscator reversal | Skidfuscator and Aidsfuscator reversals (whole-jar passes, checked by the JVM verifier without initializing classes), applied automatically by `decompile` on a `HIGH` diagnosis; ZKM opaque-predicate flags proved constant over the whole jar are folded | Renamed names cannot be recovered without a mapping; other obfuscators are detected, not reversed |
| Renaming | Deterministic aliases or explicit mapping files for class sets, private members, manifests, `META-INF/services` and literal reflection calls; ProGuard/R8 mapping import restricted to what can be applied safely, with per-reason skip evidence; portable names for case-colliding classes and non-identifier member names before decompiling | Public/virtual member renaming needs hierarchy-aware analysis; reflection through variables is not followed |
| Inputs | `.class`, `.jar`, multi-release jars (base version), executables with an embedded jar, bundles of jars, Android APK/dex (converted by dex2jar in a worker), with input identification from the bytes | App bundles (`.aab`) and split-APK sets are identified, not converted |
| Diagnostics | Static invokedynamic, reflection, class-loading and crypto references (clues only, never a verdict); compiler fingerprint (javac, ecj, Kotlin, Scala, Groovy); embedded library recognition; optional Ghidra triage of bundled native libraries | Reliable packer or encryption identification is not claimed |
| Reports | `report.txt`, `report.json` (schema v1), a self-contained `report.html` confidence map, an IDE project export (see [report format](reports.md)) | Stable public Java API |
| Desktop application | Swing + FlatLaf + RSyntaxTextArea on the same pipeline: browse, decompile with progress and cancel, per-class confidence, per-method round-trip marks, engine comparison, obfuscator banner with reversal, find usages and call hierarchy, search, export, English and Portuguese | Further features are planned separately |
| Benchmarks and failure lab | Authored corpus and ProGuard fixtures; scoreboard on hash-checked Maven Central libraries (`dev`, `holdout`, `holdout2` sets); failure lab that captures, minimizes and promotes regression cases checked by `./gradlew test` | Repeated trials, readability metrics, more obfuscators in the corpus |
| Behavioral verification | Sandbox probe and evidence protocol only; target execution is disabled (see [sandbox](sandbox.md), [behavior protocol](behavior-protocol.md)) | Isolated runner, capture and paired execution; never host execution |
| Extensibility | Engine interface and an experimental pass API with an explicit built-in registry | External plugin packaging and a stable SDK |
| Distribution | `./gradlew :cli:installDist :cli:distZip` (launchers `classrevive` and `classrevive-gui`); requires a Java 21 JDK | Releases with checksums; a runtime image that does not need a separate JDK |
